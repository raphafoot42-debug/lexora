KNOWN FAILURES THAT MUST BE INVESTIGATED AND FIXED

1) TARGET CAPTURE BUG
At one point the generated video was filming SP Studio's own localhost UI instead of the target site. This must be impossible after your changes.
Add an explicit assertion that the active page/domain being recorded matches the requested target URL/domain. If not, abort the render.

2) BROWSER INTERACTION BUG
The Spark Idea submit button was previously found while disabled. The test showed:
- name field placeholder: “Prénom”

- button: “Analyser →”
The original script only filled the first field, leaving the button disabled. Make field discovery and interaction robust to disabled buttons, reactive frontends, dynamic fields, and delayed enablement.

3) VIDEO QUALITY PROBLEM
Earlier renders looked like generic AI templates: large empty areas, white/black text cards, repetitive scene cuts, static captures, huge labels, unnatural transitions, and internal labels such as HOOK/CTA/RESULT appearing in the video.
The final system should primarily show the real product in action. Avoid explanatory cards unless they are genuinely useful and visually integrated.

4) TIMING / DURATION BUGS
Earlier renders failed quality checks at 34.07 s and 15.03 s because the allowed range was too rigid. Duration policy must be flexible and content-driven. Target roughly 18–24 seconds for TikTok, but accept a valid shorter or slightly longer result when the story naturally requires it.
More importantly, narration must not end far before the video. Validate audio/video duration relationship.

5) VOICE BUG / QUALITY
Windows TTS previously failed on scene 2. Local Windows TTS may be used as a fallback, but it should not be the final-quality voice. Build a provider abstraction for neural TTS (for example ElevenLabs/Azure/Google/OpenAI-compatible provider via environment variables) without hard-coding credentials. Local fallback must remain available for testing.
Do not pretend Windows SAPI sounds human. The architecture should make realistic TTS the preferred production path.

6) FFmpeg / FONTCONFIG BUG
FFmpeg failed with Fontconfig on Windows because drawtext used a font reference that required unavailable fontconfig config. Use a real Windows font path / fontfile discovered at runtime. Escape the path correctly. Do not depend on Linux font paths.

7) FFmpeg MUSIC BUG
A complex aevalsrc filter failed on Windows with:
“No option name near '48000\\:d=35'”
Replace fragile expression-string handling with robust filter arguments or file-based generation. Test the exact Windows command shape.
