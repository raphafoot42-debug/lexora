JULES — SP STUDIO V18 : AUDIT FINAL + RÉPARATION COMPLÈTE

Je te donne une nouvelle base SP Studio V18 déjà durcie par un premier passage technique. Ton travail maintenant n'est PAS de simplement commenter le code. Tu dois auditer toute la base, exécuter les tests disponibles, reproduire les problèmes importants quand l'environnement le permet, corriger réellement tout ce qui doit l'être, puis laisser le dépôt propre, cohérent et testable.

OBJECTIF PRODUIT
SP Studio reçoit une URL réelle et doit produire automatiquement une courte vidéo produit verticale professionnelle :
URL → exploration réelle du site → interaction réelle → observation du résultat → sélection des meilleurs moments → storyboard → capture réelle → montage 1080x1920 → narration/musique → contrôle qualité → MP4 final.

Le rendu doit ressembler à une vraie démo produit humaine, pas à un template « vidéo IA ».

============================================================
CE QUI A ÉTÉ AJOUTÉ / CORRIGÉ DANS CETTE V18
============================================================

1. VALIDATION STRICTE DE LA CIBLE
- src/domain-validation.js a été renforcé.
- Un site distant demandé ne peut plus être remplacé par localhost, 127.0.0.1 ou un autre domaine.
- Les redirections vers un autre hostname sont refusées.
- Une équivalence www / non-www est tolérée.
- Des tests couvrent maintenant : bonne cible, localhost, autre domaine et cas local.

2. DERNIER BUG DE SÉLECTION DU CTA CORRIGÉ
- Dans src/analyser-site.js, la sélection d'un bouton n'utilise plus l'index d'une liste filtrée pour cliquer dans une autre liste DOM.
- Une résolution sémantique actionLocator() est utilisée : rôle + nom exact, puis fallback textuel.
- Un bouton doit être visible et non désactivé avant d'être retourné.
- Le CTA final utilise la même logique robuste.

3. FORMULAIRE RÉACTIF CONSERVÉ / DURCI
- Le moteur continue de remplir tous les champs visibles pertinents avant de chercher le CTA.
- fill() + frappe réelle + événements input/change/blur sont conservés.
- Le bouton disabled n'est jamais forcé.
- Le moteur attend que le frontend réactif rende réellement l'action disponible.

4. SESSION VIDÉO ANCIENNE SUPPRIMÉE
- Au début d'une nouvelle exploration, videos/session.webm est supprimé.
- L'objectif est d'empêcher qu'une ancienne session soit utilisée par erreur.

5. STORYBOARD BASÉ SUR LES MOMENTS OBSERVÉS
- src/agent-planner.js a été réécrit pour privilégier uniquement les milestones réellement observés.
- Le planner refuse maintenant de fabriquer un storyboard avec trop peu de moments observés.
- Les captions sont plus factuelles.
- Les affirmations non vérifiées du type « Spark Idea résout ton blocage » ont été supprimées.
- Le plan contient explicitement realProductOnly et noSyntheticStillFallback.

6. PLUS DE FALLBACK IMAGE FIXE SILENCIEUX
- src/generer-video.js ne transforme plus silencieusement une capture PNG en scène vidéo si une scène réelle manque.
- Si une scène n'a pas de plage vidéo observée valide, le rendu échoue proprement.
- C'est volontaire : mieux vaut signaler une capture insuffisante que produire une vidéo artificielle.

7. BUG TTS / NETTOYAGE DES ASSETS CORRIGÉ
- Le nettoyage de work/assets se faisait auparavant après la création éventuelle de la voix.
- La V18 nettoie les assets AVANT de générer la voix.
- La voix générée n'est donc plus supprimée juste avant le montage.

8. MIX AUDIO RENFORCÉ
- Le mix musique + voix utilise maintenant apad/amix/atrim pour garder une piste audio alignée sur la durée vidéo.
- Le manifest indique réellement si une narration a été générée et quel provider l'a produite.
- Windows SAPI reste un fallback de test ; les providers neuronaux restent disponibles par configuration.

9. QUALITY GATE RENFORCÉ
src/quality-gate.js vérifie désormais notamment :
- existence de l'analyse ;
- existence du storyboard ;
- existence d'une session récente ;
- cohérence URL cible / URL observée ;
- cohérence manifest / analyse ;
- résolution 1080x1920 ;
- durée 12–28 s, avec cible idéale 18–24 s ;
- présence du flux audio ;
- durée audio proche de la vidéo ;
- absence de captions contenant des labels internes ;
- absence de scènes sans plage observée ;
- absence de fallback synthétique déclaré ;
- détection de longues séquences noires ;
- détection de plans figés anormalement longs ;
- stale output / session potentiellement obsolète.

10. TESTS AJOUTÉS / RENFORCÉS
- test-domain-validation.test.js couvre les redirections hors cible.
- test-render-policy.test.js vérifie les règles « produit réel uniquement » et l'absence de fallback image fixe dans le renderer.
- Les tests TTS existants restent présents.
- package.json inclut désormais le nouveau test de politique de rendu.

11. DOCUMENTATION V18
- README.txt mis à jour.
- V18-CHANGELOG.txt ajouté.
- config.example.json ne contient plus de fausses clés à copier par erreur.

C. VÉRIFIE SPÉCIALEMENT CES RISQUES

1. Le renderer doit toujours filmer le vrai site demandé.
2. Aucun localhost ne doit apparaître dans la vidéo finale lorsque la cible est distante.
3. Aucune ancienne session ne doit être réutilisée.
4. Aucun bouton disabled ne doit être cliqué.
5. Aucun index DOM fragile ne doit être utilisé après filtrage d'une autre liste.
6. Une SPA / React / Vue peut modifier le DOM après remplissage : attendre l'état réel.
7. Une redirection externe doit être considérée comme hors cible.
8. Un popup/cookie banner ne doit pas casser le parcours si une stratégie raisonnable permet de le fermer.
9. Les captures doivent réellement correspondre aux milestones utilisés dans le storyboard.
10. Une scène manquante doit provoquer une erreur explicite, pas une invention visuelle.
11. Le texte à l'écran doit rester lisible, court et correctement positionné.
12. Aucun « HOOK », « CTA », « STORYBOARD », « DEBUG », « SCENE », « SP STUDIO » ou autre métadonnée interne ne doit être visible dans la vidéo.
13. Le produit doit occuper suffisamment l'image : pas de grands vides inutiles.
14. Le montage ne doit pas devenir une succession de cartes statiques.
15. La musique ne doit pas écraser la voix.
16. La narration ne doit pas finir beaucoup trop tôt par rapport à la vidéo.
17. Si la voix Windows est utilisée, ne la présente jamais comme une voix premium.
18. Les clés API ne doivent jamais apparaître dans les logs ou dans le dépôt.
19. Les commandes FFmpeg doivent être sûres sous Windows.
20. Les chemins avec espaces / accents doivent fonctionner.
